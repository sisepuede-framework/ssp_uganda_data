Key Design Constraints

Stateless Backend

The API holds zero session state. Every request carries the full conversation history. Session is maintained entirely in the browser (state.messages[]).

No Streaming

The /api/chat endpoint is synchronous. The full Claude + tool loop completes before any bytes are sent. Loading phrases on the frontend are purely cosmetic timers.

Surrogate ≠ SISEPUEDE

The XGBoost model is a statistical approximation trained on 1,933 SISEPUEDE runs. It predicts means of 5-year emission windows, not full year-by-year trajectories.

Chart = 2 Points Only

Charts show emissions at 2035 (2033–37 mean) and 2070 (2066–70 mean). The straight line between them is visual interpolation — not a model projection of intermediate years.

L Transform Formula

T = 0.9 × x + 0.1   (design 3 — standard, confirmed by modeler)

x = L feature value ∈ [0, 1]
T = transformation magnitude ∈ [0.1, 1.0]
Physical effect = transformer_default_magnitude × T

Reverse:  x = (T − 0.1) / 0.9
Example:  x = 0.9  →  T = 0.91  →  91% of maximum ambition

Ramp: SISEPUEDE applies T progressively over ~20–30 years via vec_implementation_ramp.
T is the TARGET at 2070, not an immediate jump.

LHS Trial Lookup Flow

# When get_scenario_variables is called:

1. load ATTRIBUTE_LHC_SAMPLES_LEVER_EFFECTS.csv  (local, ~350KB)
2. Filter to design_id=3 rows
3. Compute Euclidean distance from requested L values to each trial row
4. Select the nearest trial → future_id

5. Lookup future_id in ATTRIBUTE_PRIMARY.csv → primary_id
6. Look up primary_id in s3_model_input_index.json → directory_N

7. Fetch s3://sisepuede-data/run_database/{run_id}/model_input/region=uganda/
        model_input_{directory_N}/data.csv   (S3, cached LRU 50 entries)

8. Filter CSV to primary_id row → return variable values for requested groups
