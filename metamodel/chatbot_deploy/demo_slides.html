How it works
Two layers make this possible
⚙️

SISEPUEDE Full Model

The underlying climate model for Uganda. Runs ~100,000 simulations, each exploring a different combination of policy levers and uncertainty parameters — renewable energy adoption, land use change, transport policies, and more.

Computationally intensive and technically complex. Not accessible in real time or to non-technical audiences.

run once · offline
→
🤖

XGBoost Surrogate Model

A machine learning model trained on those 100k simulations. It learns the input–output relationship of SISEPUEDE and can reproduce its predictions in milliseconds — enabling real-time exploration of multiple scenarios without re-running the full model.

Fast and powerful, but still requires structured technical inputs: lever values, variable IDs, numeric ranges.

fast · multi-scenario
→
💬

Claude AI Agent

The interface layer. It receives plain English policy questions from any user, translates them into the technical inputs the surrogate needs, runs predictions, and returns results as charts and clear language — no modeling expertise required.

Bridges the gap between policy conversations and quantitative model outputs — making SISEPUEDE results accessible to ministers, planners, and development partners.

natural language · real time

Why build this
Three reasons this tool matters
01

Easier access to SISEPUEDE results

SISEPUEDE produces rich outputs but requires deep technical expertise to query. This tool lets ministers, planners, and development partners explore Uganda's climate scenarios directly — without understanding model internals.

policy language → model inputs
02

Translate policy questions into the model

An AI agent maps natural language questions — "What if we invest $200M in bus rapid transit?" — into structured lever inputs, runs the surrogate, and returns grounded answers with charts and numbers.

question → prediction → insight
03

Stress-test with real questions

Users ask things we haven't anticipated. This surfaces gaps in model coverage, limits of the surrogate, and scenarios that need better parameterization — before the model informs high-stakes decisions.

discover model boundaries

Next steps
Four areas to improve

Model & data

  • Define target time points — pin exactly which years matter for policy decisions (2030, 2035, 2050 NDC milestones)
  • Ground factual answers in verified data — NDC targets, GDP, energy mix from official Uganda sources, not AI training knowledge
  • Systematic agent stress-testing — identify where natural language → lever mapping breaks down against the XGBoost

Presentation & UX

  • Scenario-tailored charts — vary chart type by question: emissions by sector for coverage, cost/benefit timeline for investment, MAC curve for prioritization
  • Improve result formatting — units, uncertainty ranges, sector labels, axis clarity
  • Continuous user testing — both technical (modelers checking outputs) and non-technical (policy audience checking interpretability)
